# Lumen (`lumen`)

Игра для изучения языков. Словарь — ночное небо: слова и устойчивые фразы это
звёзды, тематические паки — созвездия, а яркость звезды в **люменах (lm)** равна
вероятности вспомнить слово прямо сейчас. Основная механика: в центре экрана
слово или фраза на родном языке, вокруг 5–6 вариантов на изучаемом, нужно
соединить с одним. При верном соединении вариант проговаривается.

Приложение **полностью бесплатное**, без рекламы и подписок, живёт на
добровольных донатах. Отсюда главное инженерное требование: стоимость одного
пользователя в месяц стремится к нулю, то есть **offline-first без обязательного
сервера**.

## Быстрый старт

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # Drift
flutter gen-l10n                                            # ARB → Dart
dart run tool/build_content.dart --lang de                  # сборка content.db + манифеста аудио
flutter run
```

Ключи (нужны только начиная с M6) передаются через `--dart-define`, в
репозитории их нет:

```bash
flutter run --dart-define=SENTRY_DSN=... --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_ANON_KEY=...
```

## Технологии

Стек сознательно повторяет `athlete_index` — тот же канал Flutter, те же
библиотеки состояния, навигации, БД и CI. Это экономит время на настройке и
позволяет переносить решения между проектами.

| Слой | Технология |
| --- | --- |
| Платформа | Flutter (канал **beta**, 3.47.x / Dart 3.13.x), Android + iOS |
| Состояние | `flutter_riverpod` (Notifier/NotifierProvider, производные Provider) |
| Навигация | `go_router` (`StatefulShellRoute.indexedStack` для 4 вкладок, redirect-гейты) |
| Локальная БД | `drift` + `drift_flutter` (SQLite), кодоген `drift_dev`/`build_runner` |
| Контентная БД | предсобранная read-only SQLite в ассетах, открывается отдельным `NativeDatabase` |
| Звук | `just_audio` (пул из 2–3 плееров, предзагрузка следующего файла) |
| Аудио | всё в ассетах приложения; докачка появится только со вторым языком изучения |
| Отрисовка неба | `CustomPainter` + `GestureDetector` (карта созвездий, круг, анимации) |
| Бэкенд (M6, опционально) | `supabase_flutter` — auth, снимок JSONB, RLS, Realtime |
| Уведомления | `flutter_local_notifications` (ежедневное напоминание) |
| Мониторинг | `sentry_flutter` (краши; PII выключен, трейсинг 0) |
| Аналитика | собственный фасад `AnalyticsService` (логирующая реализация по умолчанию) |
| Локализация | `flutter_localizations` + gen-l10n (ARB), `LocalizedText` для доменного контента |
| Прочее | `path_provider`, `share_plus`, `url_launcher`, `flutter_launcher_icons` |
| Тесты | `flutter_test`, `mocktail` |
| Инструменты сборки контента | Dart CLI в `tool/`, пакет `sqlite3`, `csv`, `yaml` |

### Что берём из athlete без изменений

`flutter_riverpod`, `go_router`, `drift`/`drift_flutter`, `supabase_flutter`,
`sentry_flutter`, `flutter_local_notifications`, `share_plus`, `path_provider`,
`url_launcher`, `flutter_launcher_icons`, `flutter_lints`, `mocktail`,
`build_runner`, `drift_dev`, `flutter_localizations` + gen-l10n.

### Что добавляем

`just_audio` (озвучка верного ответа — часть ядра игры) и `sqlite3` (только в
`tool/`, для сборки контентной БД). Больше ничего: сетевого клиента в MVP нет
вообще, потому что аудио целиком лежит в ассетах.

### Что не берём

`fl_chart` — графиков в MVP нет, экран статистики яркости появится не раньше M5
и, возможно, обойдётся своим `CustomPainter`. `pdf` и `reactive_forms` — не нужны:
отчётов нет, форм в игре почти нет.

Feature-first + clean layering, как в `athlete_index`:

```

    local/      Drift-схема пользовательских данных, БД, кодеки
    remote/     CloudSync (интерфейс) + SupabaseCloudSync (M6)
    repositories/  Riverpod-контроллеры + bootstrapPersistence
  domain/
    entities/   Concept, Lexeme, Phrase, Constellation, Tier, WordState, PlayerState…
    srs/        ЧИСТЫЕ функции FSRS: DSR-модель, интервалы, яркость в люменах
    scoring/    ЧИСТЫЕ функции очков: множители скорости, комбо, режим, итог забега
    calibration/ ЧИСТЫЕ функции адаптивного теста: гребёнка, бинарный поиск, засев яркости
    scheduler/  ЧИСТЫЕ функции подбора пула на сессию и выбора режима по яркости
  features/
    onboarding/ выбор языков, калибровка неба
    game/       круг, забег, уровень, озвучка
    sky/        карта созвездий, ярусы, прогресс
    ritual/     дневной ритуал: Восход → уровень → ночной вызов
    challenge/  ночной вызов и шаринг результата
    profile/    орбита, искры, статистика, свои слова
    settings/   язык, звук, темп, донаты, экспорт/удаление данных
    shell/      нижняя навигация
tool/           CLI сборки и валидации контента
assets/
  content/      de.db (предсобранная, read-only)
  audio/        de/ — вся озвучка языка целиком, все ярусы
test/           домен + фичи + смоук
```

## Инварианты

Нарушить легко, поэтому вынесено отдельно.

- **`domain/srs`, `domain/scoring`, `domain/calibration`, `domain/scheduler` —
  чистый Dart.** Никаких зависимостей от Flutter, Drift, сети и `dart:io`. Это
  позволяет покрывать их быстрыми юнит-тестами; CI-гейт покрытия `domain/srs` и
  `domain/scoring` ≥ 90 %.
- **Две базы данных, не одна.** `content.db` — read-only, поставляется собранной,
  никогда не мигрируется на устройстве, заменяется целиком при обновлении.
  `user.db` — Drift с миграциями, только пользовательское состояние. Ни одна
  таблица не живёт в обеих.
- **Яркость (lm) не хранится как источник правды.** Источник — тройка FSRS
  `(difficulty, stability, lastReview)`. `lm` вычисляется на лету и кешируется в
  колонке только для быстрой сортировки; при расхождении верна тройка.
- **Скоростной множитель применяется только к словам с яркостью ≥ 40 lm.**
  На новом материале таймера нет вообще. Это правило геймдизайна, а не UI: оно
  живёт в `domain/scoring` и покрыто тестами.
- **Каждое верное соединение озвучивается.** Звук не блокирует переход к
  следующему кругу: он играет поверх анимации разворачивания. Без аудио язык
  не запускается — концепт без файла озвучки не проходит валидацию контента.
- **Персистентность — write-through.** Изменения контроллеров пишутся в Drift
  сразу, загрузка выполняется до первого кадра (`bootstrapPersistence`), чтобы не
  мигал онбординг.
- **Новые пользовательские данные добавляются во все три места:** Drift-схема
  (+ миграция), `bootstrapPersistence` (загрузка + write-through) и облачный
  снимок (`encodeUserData` / `decodeUserData` / `mergeUserData`) — последнее с M6.
- **Любой новый контент — сразу `LocalizedText` на все языки интерфейса;**
  строки UI — во все ARB-файлы.
- Числовые константы геймдизайна (пороги lm, множители, длины сессий) помечаются
  `TODO(balance)` и меняются в одном месте — `domain/scoring/balance.dart`.
  Данные контента — `TODO(data)` со ссылкой на источник.

## Контент и мультиязычность

Мультиязычность стоит O(N), а не O(N²), потому что хранятся не пары переводов,
а граф концептов:

```
Concept { id, tier, theme, freqRank, pos }
  ↳ Lexeme { conceptId, lang, form, article, gender, audioId, note }
  ↳ Phrase { id, conceptIds[], lang, template, slots, register, audioId }
```

Языковая пара собирается на лету из любых двух наборов лексем. Новый язык —
это добавление лексем к существующим концептам.

**Размер созвездия зависит от яруса игрока:** одна и та же тема существует на
всех пяти ярусах и растёт — 12 звёзд на A0, 96 на B2. При подъёме ярусом выше
старые звёзды остаются и продолжают участвовать в повторениях.

Подробности сборки, источников и валидации — [`docs/CONTENT_PIPELINE.md`](docs/CONTENT_PIPELINE.md).

## Локализация интерфейса

Те же шесть языков, что в `athlete_index`: английский (шаблон), русский,
украинский, немецкий, итальянский, французский. ARB в `lib/core/l10n/arb/`,
конфиг — `l10n.yaml`, генерация — `flutter gen-l10n`.

Родной язык игрока (язык подсказок в игре) и язык интерфейса — **разные
настройки**: человек может учить немецкий с украинского, а интерфейс держать на
английском.

## Офлайн, облако, приватность

- **M0–M5 работают полностью офлайн.** Ни одного обязательного сетевого вызова:
  контент в ассетах, прогресс в Drift, **вся озвучка — локальные файлы**.
  Сетевого клиента в проекте на этом этапе просто нет.
- **Единственное сетевое место — ежедневный «ночной вызов»:** статический JSON на
  CDN, один файл в день на язык. Деградирует мягко: без сети играется всё, кроме
  вызова.
- **Аудио целиком в ассетах.** Один язык изучения (немецкий) — это примерно
  5 000 слов и 1 500 фраз, в Opus 24 kbps mono около 25 МБ; вместе с базой
  Flutter и контентной БД APK укладывается в 45–55 МБ. Докачка по ярусам —
  осознанно отложенная сложность: она понадобится только когда появится второй
  язык изучения, и до этого момента её нет в коде.
- **Облако (M6, опционально):** та же схема, что в `athlete_index` — снимок
  данных пользователя одной строкой JSONB в `public.backups`, RLS по `auth.uid()`,
  объединение локального и облачного через `mergeUserData`, Realtime-подписка на
  свою строку. Аккаунт не обязателен для игры.
- **Приватность:** Sentry с `sendDefaultPii = false` и `tracesSampleRate = 0`;
  экспорт и полное удаление данных в настройках; никакой рекламы и трекеров.

## Тесты и качество

```bash
flutter analyze          # должно быть чисто
flutter test             # домен + фичи + смоук
flutter test --coverage  # + гейт покрытия srs и scoring в CI
dart run tool/validate_content.dart --lang de   # контент: полнота, аудио, дистракторы
```

Обязательно покрыто юнит-тестами: FSRS (стабильность, сложность, интервалы,
границы), пересчёт яркости, отображение времени отклика в оценку, множители
очков и комбо, сброс комбо на быстрой ошибке, адаптивный алгоритм калибровки
(в том числе схождение на синтетических «игроках»), подбор пула сессии,
расчёт орбиты при пропусках.

## CI/CD и сборка

GitHub Actions, канал beta, экшены на рантайме Node 24 (`checkout@v5`,
`setup-java@v5`, `upload-artifact@v7`).

| Workflow | Запуск | Что делает |
| --- | --- | --- |
| `ci.yml` | push / PR | кодоген → `analyze` → `test --coverage` → гейт покрытия `domain/srs` и `domain/scoring` ≥ 90 % → валидация контента → сборка web |
| `content.yml` | вручную / по тегу | сборка `content.db` и озвучки, коммит собранных ассетов |
| `test-apk.yml` | вручную | release-APK с debug-подписью для установки на телефон |
| `release-apk.yml` | вручную | подписанный APK по секретам keystore |
| `build-ios.yml` | вручную (macOS) | неподписанная iOS-сборка — проверка компиляции |

**Секреты репозитория:** `SENTRY_DSN`; с M6 — `SUPABASE_URL`, `SUPABASE_ANON_KEY`;
для подписанного APK — `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`,
`ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS`.
